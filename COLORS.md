# Color reference & rebranding guide

This documents every color the app uses, where it's defined, and **what you have to change to rebrand**. Read the "How the system works" section first — it determines how much of a rebrand is one variable vs. a find-and-replace.

All hex values are the **actual Tailwind v4 compiled sRGB values** (converted from the OKLCH source palette), not the older v3 numbers.

---

## How the color system works (2 layers)

This is **Tailwind v4** (`@import "tailwindcss"` + `@theme inline`).

1. **Dynamic accent** — [`src/app/globals.css`](src/app/globals.css) remaps **every `teal-*` class** to a scale generated from one base color, `--accent-base` (default `#7C3AED`). The base is set at runtime from admin branding in [`src/app/layout.tsx`](src/app/layout.tsx) and defaults in [`src/contexts/BrandingContext.tsx`](src/contexts/BrandingContext.tsx) and [`src/types/settings.ts`](src/types/settings.ts).
   - **Consequence:** in this codebase, `teal-*` is NOT teal — it is the brand color. Every button accent, active tab, link, and "best time" highlight that uses `teal-*` recolors automatically when the brand color changes.
2. **Standard palette** — every other family (`gray`, `green`, `amber`, `red`, `blue`, `violet`, `indigo`, …) uses Tailwind v4 defaults. These do **not** rebrand automatically.
3. **Hardcoded hex** — a handful of literal hex values in components (participant dots, heat map, skeleton, overlay, manifest). These do **not** rebrand automatically. See the "Hardcoded values" section — this is the gotcha list for your rebrand.

### The single most important lever

Changing the brand color in Admin → branding (or `accent_color` default) regenerates this whole scale:

| Token | Default hex | Drives |
|---|---|---|
| accent-50 | `#F7F6FF` | tint backgrounds |
| accent-100 | `#EDEAFF` | partial-overlap legend chip, soft fills |
| accent-200 | `#DAD2FF` | borders/tints |
| accent-300 | `#BEAEFD` | hover tints |
| accent-400 | `#9E7FF7` | toast icon, hover |
| **accent-500** | **`#7C3AED`** | active tabs, "best available" ring, primary accent |
| accent-600 | `#632DBF` | accent button text/border, link hover |
| accent-700 | `#4A2093` | pressed states |
| accent-800 | `#331469` | dark accent text (partial banner) |
| accent-900 | `#1E0942` | darkest accent text |

The scale is generated by `color-mix(in oklch, var(--accent-base) N%, white|black)` — see [`globals.css`](src/app/globals.css) lines ~8–34. To change the whole brand, you only change `--accent-base` (one value). The shade math stays the same.

| Button | Source | Hex |
|---|---|---|
| Primary "Pick a Time" / submit | `bg-blue-600` → `hover:bg-blue-700` | `#155DFC` → `#1447E6` |

| Pick-anyway (threshold not met) | `bg-amber-500` → `hover:bg-amber-600` | `#FE9A00` → `#E17100` |

⚠️ **Two near-identical purples coexist today:** literal `violet-600 #7F22FE` (share/RSVP buttons) and brand `accent-500 #7C3AED`. They look alike now but **diverge the moment branding changes.** For a clean rebrand, decide whether share/primary buttons should follow the brand accent (swap `violet-*` → `teal-*`) or stay a fixed secondary color.

## 4. Alerts & banners

| Type | Bg | Text | Hex (bg / text) |
|---|---|---|---|
| Success (overlap found / finalized) | `bg-green-50` | `text-green-700` | `#F0FDF4` / `#008236` |
| Partial overlap | `bg-teal-50` (accent) | `text-teal-800` | `#F7F6FF` / `#331469` |
| Warning (no overlap) | `bg-amber-50` | `text-amber-700` | `#FFFBEB` / `#BB4D00` |
| Danger / error | `bg-red-50` | `text-red-600` | `#FEF2F2` / `#E7000B` |
| Info (instructions) | `bg-blue-50` | `text-blue-700` | `#EFF6FF` / `#1447E6` |
| Bookmark prompt | `bg-indigo-50` | `text-indigo-700` | `#EEF2FF` / `#432DD7` |

Semantic colors (success=green, warning=amber, danger=red) should usually **stay** through a rebrand — users rely on those conventions. Rebrand the *accent*, not the alert semantics, unless the new brand specifically calls for it.

## 10. Hardcoded values that will NOT rebrand automatically

This is the critical list for your rebrand. These are literal hex/rgba in source, unaffected by the accent variable:

| Value | Where | Purpose |
|---|---|---|
| `#7C3AED` | `BrandingContext.tsx`, `settings.ts`, `globals.css` `--accent-base` | **default brand color** — change this first |
| `#14B8A6` | `manifest.ts` `theme_color` | ⚠️ PWA theme color — still defaults to teal, **inconsistent** with `#7C3AED` accent |
| `#14B8A6` / `rgba(20,184,166,α)` | `TimeGridSlot.tsx`, `TimeGrid.tsx` legend | overlap heat map (stays teal regardless of brand) |
| `PARTICIPANT_COLORS` (12 hex) | `TimeGridSlot.tsx` | participant dots |
| `#7C3AED` → `#6D28D9` | `globals.css` `.prose-editor a`, `.rich-text-display a` | rich-text link color (hardcoded, not the accent var) |
| `#9CA3AF`, `#D1D5DB`, `#F3F4F6`, `#E5E7EB` | `globals.css` slot hover + skeleton | grays (note: these are v3 hex, ~identical to v4 class grays) |
| `rgba(0,0,0,0.08)` / `0.45` | modal scrims/overlays | dim layers |

## Rebranding checklist

When the new palette is chosen, do these in order:

1. **Set the brand accent** — update `accent_color` default in `BrandingContext.tsx` + `settings.ts`, and `--accent-base` in `globals.css`. This recolors all `teal-*` usage instantly. (Or just set it once in Admin → branding if you only want a runtime change.)
2. **Fix the PWA theme color** — `manifest.ts` `theme_color` currently hardcodes `#14B8A6`; point it at the brand accent (or the new brand hex).
3. **Decide the secondary/primary button color** — resolve the `violet-600` vs `accent` duplication. Either swap `violet-*` → `teal-*` (follow brand) or pick an intentional fixed secondary.
4. **Recolor the overlap heat map** — replace `rgba(20,184,166,…)` in `TimeGridSlot.tsx` + the legend swatch in `TimeGrid.tsx` with the brand hue (or keep a deliberate contrasting "data" color).
5. **Refresh participant dots** if desired — `PARTICIPANT_COLORS`; keep ~12 distinct hues at similar lightness.
6. **Update rich-text link color** — `.prose-editor a` / `.rich-text-display a` in `globals.css`.
7. **Leave semantic colors alone** unless the brand demands otherwise — green=success, amber=warning, red=danger/deadline-passed are conventions users rely on.
8. Rebuild (`npm run build`) and eyeball: buttons, active tabs, overlap grid, alerts, deadlines, toasts.

### Tip for the AI palette pass
Give the AI: the brand logo/colors, **and the categories above** (accent, semantic success/warning/danger, neutral gray scale, 12 participant hues, overlap-heat hue). Ask it to return one **accent base hex** plus optional overrides for the heat map and participant set — not a full repaint of the semantic colors. That keeps the rebrand to ~6 edits instead of hundreds.
